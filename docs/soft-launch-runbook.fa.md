# راهنمای Soft Launch نیشا

مراحل عملی قبل از soft launch با ۵–۱۰ فروشنده واقعی. این سند مکمل [`qa-launch-checklist.fa.md`](./qa-launch-checklist.fa.md) است و روی اشتراک پلتفرم، کارت پرداخت و smoke test تمرکز دارد. برای جزئیات امنیتی Wave 1 ببین [`security-hardening-wave1.md`](./security-hardening-wave1.md). راهنمای دیپلوی: [`PRODUCTION_DEPLOYMENT.md`](./PRODUCTION_DEPLOYMENT.md). نمونه Nginx: [`../deploy/nginx.conf.example`](../deploy/nginx.conf.example).

## ۰) Day-0 — امروز بفروش (چک‌لیست سریع)

هدف: همان روز دامنه بالا باشد، smoke سبز باشد، و ۵–۱۰ فروشنده دعوت شوند.

| # | کار | اگر نکنی |
|---|-----|----------|
| 1 | روی سرور: `git pull origin main` | کد قدیمی می‌ماند |
| 2 | `cd backend && alembic upgrade head` (شامل `reservation_expires_at`) | انقضای موجودی/سفارش خراب |
| 3 | env پروداکشن: `EMAIL_PROVIDER` ≠ `console`، `FRONTEND_BASE_URL` واقعی، `PRIVATE_UPLOAD_DIR`، `JWT_SECRET_KEY` قوی، CORS درست | API بالا نمی‌آید / ایمیل / رسید |
| 4 | `docker compose -f docker-compose.prod.yml up -d --build` | سایت عمومی نداری |
| 5 | ادمین → `/admin/settings` → **کارت اشتراک پلتفرم** | فروشنده نمی‌تواند پلن بخرد |
| 6 | Smoke: ثبت‌نام فروشنده → راه‌اندازی → داشبورد؛ سفارش مهمان + آپلود رسید؛ اشتراک + تایید ادمین | هنوز فروشنده دعوت نکن |
| 7 | بکاپ DB + `uploads` + `private_uploads` | ریسک داده |
| 8 | دعوت ۵–۱۰ فروشنده با پیام زیر | درآمد صفر |

**پیام دعوت (تلگرام / دایرکت):**

> فروشگاه آنلاینت را رایگان بساز، با کارت‌به‌کارت بفروش، روی هر سفارش کارمزد نده.
> لینک: `https://YOUR-DOMAIN`

قالب‌های کامل PV، فالوآپ و تقویم ۱۴روزه اینستاگرام: [`soft-launch-marketing.fa.md`](./soft-launch-marketing.fa.md) · نسخه HTML: [`soft-launch-marketing.html`](./soft-launch-marketing.html).

روی فروش تمرکز کن؛ Wave 2 امنیت و فیچرهای اضافه را بعد از یک هفته با فروشنده واقعی انجام بده.

## ۱) مایگریشن دیتابیس

روی محیط staging/production:

```bash
cd backend
alembic upgrade head
```

مطمئن شو مایگریشن پلن‌های اشتراک (`subscription_plans` و جداول مرتبط) و `reservation_expires_at` اعمال شده است.

## ۲) تنظیم کارت اشتراک در ادمین

1. وارد پنل ادمین شو: `/admin/settings`
2. بخش **کارت اشتراک پلتفرم** را پر کن: شماره کارت، نام صاحب کارت، بانک
3. اگر شماره کارت خالی باشد، صفحه تنظیمات ادمین هشدار می‌دهد و فروشنده بعد از checkout پیام «کارت پلتفرم هنوز تنظیم نشده» می‌بیند — soft launch اشتراک بلاک است تا این فیلد پر شود
4. ذخیره کن و یک بار صفحه را رفرش کن تا مقادیر تایید شوند

## ۳) Smoke test اشتراک (فروشنده رایگان → ارتقا)

با یک حساب فروشنده روی پلن رایگان:

1. `/seller/discounts` → باید گیت ارتقا دیده شود (ساخت کد تخفیف قفل)
2. `/seller/subscription` → پلن **حرفه‌ای** را انتخاب کن → چک‌اوت کارت‌به‌کارت
3. شماره کارت پلتفرم نمایش داده شود؛ مبلغ را (در تست می‌توانی واریز تستی/شبیه‌سازی کنی) و **رسید** را آپلود کن
4. وضعیت فروشنده: **در انتظار تایید مدیر**
5. ادمین: `/admin/subscriptions` → فاکتور را **تایید** کن
6. فروشنده را رفرش کن: پلن فعال عوض شده باشد و صفحه تخفیف/آمار/تنظیمات مطابق entitlement باز شود

## ۴) Smoke test خرید مهمان (پلن پایه+)

1. فروشگاهی که پلن **پایه یا بالاتر** دارد و در تنظیمات فروشگاه «خرید مهمان» را روشن کرده باشد
2. از ویترین عمومی بدون لاگین مشتری، یک سفارش کامل ثبت کن (سبد → چک‌اوت → آپلود رسید)
3. فروشنده سفارش را در پنل ببیند و وضعیت را جلو ببرد
4. روی فروشگاه پلن **رایگان** انتظار داشته باش که خرید مهمان فعال نشود / گیت entitlement اعمال شود

## ۵) کانال‌های عملیاتی (چک‌لیست env — بدون قرار دادن secret در git)

قبل از soft launch واقعی، در env پروداکشن/استیجینگ این‌ها را فعال/پیکربندی کن (مقادیر را فقط در secret store نگه دار):

- [ ] `SENTRY_DSN` (فرانت و بک‌اند در صورت جدا بودن)
- [ ] SMTP/Resend واقعی — در production مقدار `EMAIL_PROVIDER=console` باعث **عدم استارت** API می‌شود
- [ ] `FRONTEND_BASE_URL` دامنه واقعی (نه localhost) تا لینک‌های ایمیل درست باشند
- [ ] کانال SMS (اگر در این فاز استفاده می‌شود)
- [ ] URL عمومی API و CORS مطابق دامنه نهایی
- [ ] `PRIVATE_UPLOAD_DIR` برای رسید پرداخت/اشتراک (عمومی نیست؛ از `/api/v1/media/private/...` با توکن کوتاه‌عمر سرو می‌شود)
- [ ] `ORDER_RESERVATION_MINUTES` (پیش‌فرض ۲۰) — موجودی سفارش‌های پرداخت‌نشده بعد از انقضا برمی‌گردد
- [ ] `ALLOW_DEMO_SEED` فقط در صورت نیاز به seed دمو در پروداکشن؛ پیش‌فرض خاموش. seed دیگر پسورد ادمین موجود را عوض نمی‌کند

## ۵.۱) نکات امنیتی Wave 1

- ثبت‌نام مجدد روی ایمیل تاییدنشده دیگر پسورد را عوض نمی‌کند (ضد account takeover)
- WebSocket دیگر JWT/پسورد را در query string نمی‌گیرد؛ ابتدا `POST /api/v1/ws/tickets/...` سپس `?ticket=`
- خروجی CSV فروشنده برای جلوگیری از CSV formula injection سانیتایز می‌شود
- رسیدهای پرداخت و اشتراک از `/uploads` عمومی خارج شده‌اند

## ۶) بکاپ و بازیابی

1. قبل از soft launch: بکاپ کامل دیتابیس + فایل‌های آپلود **و** `private_uploads`
2. یک بار **restore** روی محیط جداگانه تست کن تا بکاپ سالم باشد
3. محل نگهداری بکاپ و مسئول بازیابی را مشخص کن

## ۷) معیار Soft Launch (از چک‌لیست QA)

مطابق بخش soft launch در [`qa-launch-checklist.fa.md`](./qa-launch-checklist.fa.md):

- حداقل **۵ فروشنده** واقعی فروشگاه ساخته و حداقل یک سفارش کامل پردازش کرده‌اند
- **یک هفته** پایداری: بدون باگ بلاکر / خطای ۵۰۰ تکرارشونده
- کانال بازخورد فروشنده‌ها فعال باشد
- کارت اشتراک و smokeهای بخش ۳ و ۴ سبز باشند

وقتی این موارد سبز شد، می‌توانی به لانچ عمومی (بخش ۴ چک‌لیست QA) بروید.
